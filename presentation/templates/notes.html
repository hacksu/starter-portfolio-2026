Before you startsetup

Setup - do this before anyone arrives

  • Editor open on the projector at a font size the back row can read. VS Code, zoom level 2 or 3.
  • An empty folder with one empty file in it: index.html.
  • A browser window beside the editor showing that file, so a save and a refresh are both visible at once.
  • A photo in the same folder for the img section. Something you can point at.
  • Already signed in to Vercel. Do not spend workshop time on a login screen.
The shape of this session: three slides of context, then you build a page live while the deck sits behind you as a reference. They should watch a file turn into a website.
Slide 10:00

Title

  • Ask: "Who here has never written a line of HTML?" Reassure the hands that go up, they are the target audience.
  • Set the promise: in forty minutes you will have written a web page and put it on the internet at a real address.
  • Say what we are skipping: React, npm, build tools, the terminal. All real, all worth learning later, none needed today.
  • Run through the five numbered items so they know the shape of the session.
Slide 20:01

Every Website Is Three Languages

  • Ninety seconds. This is orientation, not content.
  • The analogy that lands: HTML is what you say, CSS is how it is dressed, JavaScript is what it does when poked.
  • Be clear that today is mostly HTML, and that it is the part nobody can skip.
Slide 30:02

A Web Page Is Just a File

  • This is the idea that surprises beginners most: no server, no special software, no upload. It is a text file your browser knows how to read.
  • Mention index.html being the special name, because it comes back at deployment.
Demo: double-click an HTML file on the desktop and point at file:/// in the address bar. A website, with no internet involved.
Slide 40:04

A Tag Wraps Around Content

  • Point at each part of the diagram and name it out loud: opening tag, content, closing tag.
  • The slash is the whole difference between opening and closing. Say it explicitly, it is a real stumbling block.
  • Nesting: close them in the order you opened them. Compare it to brackets in maths if that helps the room.
Slide 50:06

Every Page Starts the Same Way

  • head is about the page, body is the page. That one sentence is the whole slide.
  • Do not explain DOCTYPE beyond "it tells the browser this is modern HTML, always put it first".
  • Tell them the title is the browser tab, then point at your own browser tab.
SWITCH TO THE EDITOR NOW. Type this skeleton from scratch into the empty index.html, save, refresh the browser. A blank white page with "Hello!" on it. From here on the deck is only there to show the next tag.
Slide 60:09

Headings and Paragraphs - typed live

  • Flip to the slide, read the tag, flip back to the editor and type it. Save. Refresh. Repeat.
  • Type an h1 with your own name, then an h2, then an h3, so they watch the sizes step down.
  • Write a paragraph about yourself. Make it real, they remember it better.
  • Then the enter-key demo: press enter three times inside a paragraph, save, refresh, nothing moves. HTML ignores your line breaks. A new paragraph needs a new <p>.
Invite them in: anyone with a laptop should be typing along by now. Say so out loud and pause ten seconds for people to catch up.
Slide 70:13

Lists - typed live

  • Type a ul of things you know or like. Add an li, save, refresh, add another.
  • Then change the ul to an ol and refresh. Bullets become numbers and nothing else changed. That lands the difference better than explaining it.
  • Common mistake worth showing: an li on its own outside a list. Do it wrong on purpose.
Slide 80:17

Links and Images - typed live

  • Type a link to something real and click it in the browser. That is the moment the page stops feeling like a document.
  • Show all three kinds: a full web address, another file, and a mailto:.
  • Drop in the photo you prepared. Point out that src is just a filename sitting next to the HTML file.
  • Break it on purpose: misspell the filename, refresh, and watch the alt text appear. Fastest possible explanation of why alt matters.
Checkpoint: the page now has a heading, a paragraph, a list, a link, and an image. Say that out loud. It is a real web page and it took nine minutes.
Slide 90:22

A Bit of CSS - typed live

  • Make style.css next to the HTML file, add the <link> in the head, and prove the connection with something obvious like background: hotpink.
  • Then tone it down and do the useful ones: color, font-size on the h1, width on the image.
  • Selector, brace, property, value. Name the parts once, then keep typing.
  • Do not teach the cascade, specificity, flexbox, or grid. No time, and they do not need any of it to make something they like.
Ask the room for a colour and use whatever gets shouted. Keeps people watching, and makes the point that CSS is instant feedback.
Slide 100:28

A Bit of JavaScript - typed live

  • Four minutes, one example. Add a button and make it change the heading.
  • Say the three steps out loud as you type them: find something, change it, react to a click.
  • Point at the id on the tag and the matching name in getElementById. That connection is the bit people miss.
  • Mention the script goes at the bottom of the body so the tags it looks for already exist.
  • Do not explain variables, functions, loops, or types. Not today.
Slide 110:28

Your Turn - hands off, they type

  • Stop presenting. Put the starter repo on screen, leave the slide up, and walk the room for six minutes.
  • Say out loud that they can either grab the starter or keep going with the page you built together. Both are fine.
  • Anyone with nothing on screen yet needs help first. Usually it is an unsaved file or an unclosed tag.
  • Tell them what happens next: in a few minutes you are going to put a page on the internet, so they should get something they like on screen now.
Watch the clock. Six minutes goes fast and the deployment demo is the payoff of the session. Call time at 0:34 even if people are mid-edit, they can keep working through the last slides.
Slide 120:34

Putting It on the Internet - do it live

  • Bring everyone back. This is the payoff, so do it for real on the projector.
  • Go to vercel.com/new and drag the folder in. No terminal, no Git, no repository. Say that clearly, because most people assume deployment is hard.
  • Read the resulting URL out loud and open it in a fresh tab.
  • Mention GitHub Pages as the alternative for when they are already using Git, then move on. Do not teach Git.
  • Tell them to do the same with their own folder tonight, and that it takes about a minute.
Demo: open the live URL on your phone and hold it up. A file from the laptop, on the internet, on a device that never touched it.
Slide 130:38

Questions and Contact

  • Your LinkedIn and GitHub are on the slide, and the QR code goes to LinkedIn. Tell people to scan it now rather than meaning to later.
  • Point at MDN specifically. Tell them to prefer it over w3schools when the two disagree.
  • If anyone got a URL live during the session, ask them to share it with the room.
  • Stay behind for whoever is stuck. It is almost always an unclosed tag or an unsaved file.
